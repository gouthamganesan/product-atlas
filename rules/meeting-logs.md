# `wiki/meeting-logs/`

Notes from team meetings worth sharing wiki-wide. Start every page from `meeting-log.md` in `product-building-tools/templates/`, which carries the section structure. Keep the frontmatter as the template fills it in. `type: meeting`.

## No raw transcripts

Do not paste a transcriber's output into the page, and do not attach it. Read it, write the note from it, leave it in the recorder.

A transcript is machine output. It is usually wrong about who said what, it is often in a language most readers of the page cannot read, and at a hundred-odd kilobytes it buries the note it is attached to. The value is in the reading, and the note is where that value belongs.

Where attribution in the note is inferred rather than recorded, say so under *About this record* instead of presenting a guess as fact.

## No transcript-tool links

Never link a recording or transcription tool from a page here. That includes the meeting recorder share links (for Wispr Flow, `notes.wisprflow.ai/shared/...`), and any equivalent from another recorder.

Who can open such a link is set inside that tool, per meeting, and nobody reading the wiki can tell, so the link either leaks a recording or dead-ends. It also outlives nothing: the wiki page is meant to be the record, so anything worth keeping belongs in the page itself.

## Cross-referencing

A meeting that changes what a product doc says gets a section listing those pages as wikilinks and what each one now contradicts. Do not edit the product docs from the meeting note; that is a separate call.

No internal tracker IDs (Plane, the team tracker, team chat). Describe the work instead.
