# Document metadata

Use the templates as starting points and fill the placeholders before sharing. Every wiki page should have `title`, `description`, `type`, `status`, `created`, `lastModified` and `audience`. Dates use `YYYY-MM-DD`.

Types: `feature`, `rules`, `flow`, `reference`, `prd`, `meeting`, `decision`, `competitor-note`, `research`. Status is `draft`, `published` or `deprecated`; audience is `internal` or `public`. These are descriptive labels, not permissions.

PRDs name an owner and the relevant product slugs. Optional design links have a platform label. Competitor notes name the competitor. Leave unavailable links empty rather than inventing URLs. Keep platform differences in the body.

Use `feature` for a product-area index and `reference` for general indexes, roadmap and news. Add `## Related` and `## Changelog` to product docs and PRDs. When a decision is superseded, mark it deprecated and link its replacement.

This starter does not include a site or validator. If the team connects one, align these formats with that site's real schema before publishing.
